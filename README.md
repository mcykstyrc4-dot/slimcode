# Slim Code Lab — одностраничный лендинг

Редизайн сайта сети салонов аппаратной коррекции фигуры «Slim Code Lab»
(LPG-массаж, RSL-скульптурирование, миостимуляция, прессомассаж, кавитация).

Лендинг — один файл **`index.html`**: HTML + CSS + JS, без сборки и фреймворков.
Открывается двойным кликом, заливается на любой хостинг как статика.

## Файлы

| Файл | Что это |
|---|---|
| `index.html` | лендинг целиком: разметка, стили и скрипты в одном файле |
| `privacy.html` | политика конфиденциальности (шаблон) |
| `terms.html` | пользовательское соглашение (шаблон) |
| `consent.html` | согласие на обработку персональных данных (шаблон) |
| `legal.css` | общие стили трёх юридических страниц |
| `assets/` | фирменный логотип, иконки и обложка для соцсетей |
| `telegram-proxy.php` | приём заявок и отправка в Telegram — для хостинга с PHP |
| `telegram-worker.js` | то же самое для Cloudflare Workers |
| `robots.txt` | правила обхода + ссылка на карту сайта |
| `sitemap.xml` | карта сайта |

Юридические страницы намеренно закрыты от индексации
(`<meta name="robots" content="noindex, follow">`), пока в них шаблонный текст.
После заполнения реквизитов уберите `noindex` и добавьте страницы в `sitemap.xml`.

## Дизайн-решения

- **Цвет.** Глубина набирается оттенками, а не заливкой: тёмный винный
  (`--wine-950 … --wine-600`), кремовый текст (`--cream`), золото (`--gold`)
  на тонких деталях. Яркий красный (`--accent`) — только основные кнопки,
  бейджи акций и активная точка карусели.
- **Секции чередуются** тёмная / светлая — это и даёт ритм вместо сплошного алого.
- **Иерархия кнопок.** На экране одна залитая CTA; второстепенные действия —
  текстовые со стрелкой. Обводка есть только у кнопки WhatsApp.
- **Типографика.** Manrope (гротеск) + Cormorant Garamond (акцентная антиква),
  системные фолбэки на случай, если Google Fonts недоступны.
- **Mobile-first.** Базовые стили — мобильные, медиазапросы только «вверх»
  (600 / 900 / 1100 px).
- **Анимации** ненавязчивые: появление блоков при скролле, счётчики, ховеры.
  Полностью отключаются при `prefers-reduced-motion`.
- Без JS страница остаётся читаемой (контент виден, цифры на месте).

## Логотип и фирменный стиль

Логотип извлечён из присланного макета и разложен на варианты — все белые,
с прозрачным фоном, поэтому ложатся на любой тёмный фон:

| Файл | Где используется |
|---|---|
| `assets/logo.png` | шапка лендинга и внутренних страниц (знак + «Slim Code») |
| `assets/logo-full.png` | футер — то же плюс слоган «Стань лучшей версией себя» |
| `assets/logo-dark.png` | версия фирменным красным, для светлого фона |
| `assets/logo-mark.png` | только знак |
| `assets/favicon-32.png`, `assets/apple-touch-icon.png` | иконка вкладки и иконка на телефоне |
| `assets/og-cover.jpg` | превью при отправке ссылки в мессенджеры и соцсети |

Размеры в вёрстке заданы по высоте (`.logo img{height:…}`), пропорции считает
браузер — поменять масштаб можно одной строкой.

**Если есть исходник логотипа в векторе** (SVG, AI, EPS) — пришлите, заменю
растр на SVG: он будет чётким на любом экране и займёт пару килобайт вместо
шестнадцати. Сейчас качество ограничено присланным JPEG.

Фирменный красный с плашки логотипа — `#961F17`.

### Фирменный шрифт

В `index.html` подготовлен блок `@font-face` и токен `--brand` (ищите
комментарий «ФИРМЕННЫЙ ШРИФТ» в начале стилей). Чтобы подключить:

1. положите файлы в `assets/fonts/` — лучше всего `.woff2`;
2. раскомментируйте блок и поправьте имена файлов;
3. замените `--brand:var(--sans)` на `--brand:"SlimCode",var(--sans)`.

До этого момента `--brand` равен основному гротеску, и вёрстка не ломается.

## Что заменить на реальные данные

Все места помечены в коде комментарием `ЗАМЕНИТЬ`, а в юридических страницах —
подсвечены жёлтым (класс `.fill`).

1. **Телефоны** — `+7 (812) 000-00-00` и три номера салонов (`tel:` тоже).
2. **WhatsApp** — `https://wa.me/78120000000` (4 места: шапка контактов, футер,
   плавающая кнопка).
3. **Адреса, метро, часы работы** — блок `#contacts`.
4. **Тексты услуг, цены и сроки акций** — блоки `#services` и `#promos`.
5. **Отзывы** — тексты, имена, инициалы в аватарах, даты.
6. **Фото команды** — заменить `<div class="ph">…</div>` на
   `<img src="assets/team-1.jpg" alt="Имя, специализация" loading="lazy">`
   (пропорции 3:4, вёрстка не изменится).
7. **Фото в хиро** — блок `.hero__media`, пропорции 4:5.
8. **Соцсети** — ссылки VK / Instagram в футере.
9. **Юридические страницы** — `privacy.html`, `terms.html`, `consent.html`.
10. **Отправка формы** — блок `CONFIG` в начале скрипта, см. раздел ниже.
11. **Мета-теги** — `canonical` и домен,
    если он отличается от `slimcodelab.ru`.
12. **Микроразметка** — блок `application/ld+json` в `<head>`: реквизиты, адреса,
    телефоны, координаты салонов, часы работы, ссылки на соцсети.
    Рейтинг (`aggregateRating`) намеренно не размечен — его допустимо добавлять
    только по реальным подтверждённым отзывам.
13. **Юридические страницы** — реквизиты организации (ИНН, ОГРН, адрес), дата
    редакции, срок хранения данных, название системы аналитики.
    Тексты шаблонные: перед публикацией их должен посмотреть юрист.
    Не забудьте удалить памятку `.notice` в начале каждой страницы.
14. **`robots.txt` и `sitemap.xml`** — домен и дата `lastmod`.

## Отправка заявок в Telegram

Форма умеет отправлять заявку в Telegram. Токен бота **нельзя** класть в код
страницы: его увидит любой посетитель, и чат зальют спамом. Поэтому заявка
уходит на ваш обработчик, а он уже обращается к API Telegram.

### 1. Бот и чат

1. Создайте бота у [@BotFather](https://t.me/BotFather), получите токен
   вида `123456789:AA...`.
2. Напишите боту любое сообщение (или добавьте его в группу и напишите туда).
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и возьмите
   `result[0].message.chat.id` — это адрес, куда слать заявки.

### 2. Обработчик — один из двух

**Хостинг с PHP.** Положите `telegram-proxy.php`, например в `/api/lead.php`.
Токен и chat_id задайте переменными окружения `TG_BOT_TOKEN` и `TG_CHAT_ID`
(или впишите в начале файла). В `index.html`:

```js
CONFIG.endpoint = '/api/lead.php';
```

**Cloudflare Workers** (бесплатного тарифа хватает). Разверните
`telegram-worker.js`, укажите свой домен в `ALLOWED_ORIGINS` и задайте секреты:

```
npx wrangler secret put TG_BOT_TOKEN
npx wrangler secret put TG_CHAT_ID
```

В `index.html` пропишите адрес воркера в `CONFIG.endpoint`.

Оба обработчика: проверяют имя и телефон, режут длину полей, чистят
управляющие символы, молча отбрасывают ботов и **собирают текст сообщения
сами** — присланный страницей текст не используется, иначе через форму
можно было бы отправить в ваш чат произвольное содержимое.
PHP-версия дополнительно не принимает больше одной заявки с адреса в 15 секунд.

### 3. Запасной вариант без сервера

Если сервера нет совсем, можно заполнить `CONFIG.telegram.token` и
`CONFIG.telegram.chatId` — страница обратится к API Telegram напрямую.
**Токен при этом виден всем**, кто откроет исходный код страницы: его смогут
использовать для спама в ваш чат, и токен придётся отзывать. Годится только
как временное решение.

### Что уже сделано в форме

- маска телефона `+7 (999) 123-45-67`: понимает ввод с 8, вставку из буфера,
  правку в середине номера и Backspace по разделителям;
- проверка имени и полноты номера с подсказками под полями;
- состояние отправки на кнопке и защита от двойного клика;
- при сбое — сообщение с телефоном и ссылкой на WhatsApp, кнопка снова активна;
- скрытое поле-ловушка и отсечка мгновенных отправок: заявки ботов не уходят
  ни на сервер, ни в Telegram.

## Проверено

Хром (headless) на 390×844 и 1440×900: горизонтального скролла нет, ошибок в
консоли нет, работают меню, модалка с валидацией, карусель, счётчики, плавающая
кнопка; страница читается с отключённым JS.

Юридические страницы: горизонтального скролла нет, все ссылки оглавления ведут
к существующим разделам, внутренние ссылки между страницами не битые.
JSON-LD разбирается как валидный JSON, `sitemap.xml` — как валидный XML.

Форма (19 проверок в браузере): маска на всех сценариях ввода, валидация,
успешная отправка с разбором ушедшего запроса, поведение при ошибке сервера,
отсечка ботов. Оба обработчика прогнаны на локальной заглушке Telegram API
(14 проверок для воркера, 6 для PHP): валидные заявки доходят, некорректные
отклоняются с понятным кодом, чужой домен и GET не принимаются.
